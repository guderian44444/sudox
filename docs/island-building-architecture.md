## 1. 產品定位

小島建設模式不是獨立於數獨之外的小遊戲，而是承接數獨獎勵的長期成長系統。

核心循環：

1. 完成數獨取得金幣。
2. 使用金幣填海造陸、興建設施或雇用幫手。
3. 真實時間經過後完成建設，小島外觀永久成長。
4. 菜園、農場、果園生產原料，市場可直接收購，也可以加工提高價值。
5. 每條產業鏈最多 3～4 層，越後段的產品售價越高，但需要更多土地、設施與時間。
6. 碼頭與機場連接其他玩家；缺少加工設施的玩家可以把原料送往別人的工廠並在到貨後取得金幣。

設計原則：

- 數獨仍是主要金幣來源，不能用建設直接買樓層或排行榜成績。
- 建設等待時間以真實世界時間計算，關閉瀏覽器後仍會繼續。
- 玩家要能在手機上用單手完成選地、確認與加速。
- 初期不加入可付費購買的現金貨幣，也不做隨機抽卡式建築。
- 影響玩家資產的行為必須可重複送出而不重複扣款或發獎。
- 小島可以離線觀看；涉及金幣與多人物流的正式操作以雲端為準。
- 每種產品從第一版起就要有本地市場或下一階加工用途，不產生無法消化的孤立物品。

## 2. 建議首發範圍

首版採可長期擴充的「單人建設、生產與合作物流 MVP」。碼頭與機場已可建造，玩家互通物流以事件式 RPC 上線，不需要即時多人連線。

MVP 包含：

- 一張可拖曳、縮放的六角格像素風地圖。
- 每位玩家從半徑 1 的 7 格小島開始。
- 周圍有可填海的淺海格；首張地圖最大半徑 8，共 217 個可用座標。
- 填海造陸與單格／多格建築放置。
- 菜園、農牧、餐飲、森林／製材／造船、礦場／冶煉／造機、市場、燈塔、碼頭、單格機場與裝飾物；島主小屋同時提供五級有限容量倉庫。
- 完成蔬果直售、乳製品、果醬、巧克力、咖啡、紡織與蜂蜜蛋糕等可閉合產業鏈。
- 農場、牧場與工廠完成後停在「可領取」狀態；玩家點收成、擠奶或領成品後才嘗試進入小屋倉庫；容量不足時產品留在設施。
- 每位伙伴同時只能參與一項施工；新工程由自己的空閒伙伴或另行雇用的伙伴開工，單一工程最多再加入 2 位幫手。
- 地基、施工中、接近完工、完成四種視覺狀態。
- 離開頁面、關閉瀏覽器、手機休眠後，完成時間仍正確。
- 本機存檔、雲端恢復與不同裝置切換。
- 現有數獨、排行榜與伙伴動畫不受影響。

首版不包含：

- 即時多人同畫面。
- 玩家間直接轉移金幣。
- 無上限累積、每分鐘寫入資料庫的自動生產。
- 系統推播通知。
- 玩家彼此直接議價或轉移金幣；目前跨島市場採系統可信的 1.75 倍固定收購價。

## 3. 畫面與操作流程

### 3.1 入口

- 首頁增加固定可見的「我的小島」按鈕，手機版不能再隱藏。
- 小島使用獨立全螢幕畫面，不放在現有小型彈窗內。
- 若數獨正在計時，開啟小島不暫停數獨時間；進入前顯示一次提醒。
- URL 使用 `#island`，重新整理時可回到小島畫面，返回鍵回首頁。

### 3.2 地圖主要 UI

- 頂部：返回、島名、繁榮等級與金幣。
- 中間：六角格地圖；滑鼠按住或手機手指按住即可拖曳，右上提供 `＋／－`，桌面可直接在地圖上滾輪縮放。拖曳超過 6 px 後抑制該次格子點擊，避免移動地圖時誤選。
- 底部：顯示目前施工、生產與加工工作；點工作可定位對應格。
- 右側／手機地圖下方操作面板顯示選中格資訊、建築分類、費用與時間。
- 施工中的格子只顯示半成品與伙伴，避免倒數遮住角色；完工時間在操作面板與工作列顯示。
- 點擊施工格可查看「雇用幫手」前後的時間與花費，再次確認後才扣款。
- 所有可點區域至少 44×44 CSS px，不依賴滑鼠 hover。

### 3.3 放置流程

1. 點擊空白陸地或相鄰海格。
2. 海格先顯示填海選項；陸地顯示可放置設施。
3. 選擇建築後進入預覽狀態，合法格為綠色、衝突格為紅色。
4. 多格設施提供旋轉按鈕；不要求玩家以拖曳精準對位。
5. 確認面板明列費用、工期、占地與目前施工欄位。
6. 確認後建立交易與施工工作，地圖立即顯示半成品及工作伙伴。

## 4. 六角格地圖架構

### 4.1 座標與方向

- 建議採用「平頂六角格」（flat-top），在直向手機上可以保有較寬的建築正面。
- 邏輯座標使用 axial coordinate `(q, r)`；需要計算距離時轉成 cube coordinate。
- 六個相鄰方向固定編號 `0..5`，填海、道路、碼頭朝向與物流出入口都使用同一套方向。
- 顯示基準為寬 64、高約 56 CSS px；素材以 2 倍尺寸 128×112 px 製作。
- 橫向格距 48 px，縱向位置依 `r + q / 2` 計算。

### 4.2 初始島與擴張

- 初始陸地：中心格加一圈，共 7 格。
- 中心格預先放置兼作倉庫的島主小屋，不另外占用倉庫格；可升 5 級提高容量，最高為海島城堡。
- 其餘 6 格可自由建設，其中第一座菜園可做為教學建築。
- 世界範圍固定為半徑 8，共 217 格；未填海的格子只呈現海面。舊版半徑 4 存檔正規化後直接取得新範圍。
- 只能填造與現有陸地相鄰的海格，避免產生孤立陸塊。
- 填海後先顯示木樁、沙土與施工伙伴，完工後才成為可建築陸地。
- 後續若要擴大地圖，可提高地圖半徑，不需要改變既有座標。

### 4.3 畫面圖層

每格依下列順序組成，避免把所有狀態畫成大量獨立整圖：

1. 海面底圖與波紋。
2. 陸地中心。
3. 六方向海岸邊緣／泡沫疊圖。
4. 道路、田地或地表裝飾。
5. 建築本體或施工階段。
6. 伙伴、船隻等角色。
7. 灰塵、星光、完成提示等特效。
8. 選取框、合法性提示與倒數 UI。

海岸不製作 64 張鄰接組合圖；改用 6 個方向邊緣疊圖，依相鄰格自動組合，素材量與維護成本較低。

### 4.4 呈現技術

- MVP 使用可存取的 DOM 按鈕搭配絕對定位與 CSS transform，不先使用 Canvas。
- 整個世界放在單一 transform 容器中做平移與縮放，每個格子仍可點擊、聚焦並有 aria-label。
- 217 格目前仍以 DOM 按鈕渲染並已通過桌面檢查；手機若後續加入更多常駐角色，優先做可見區域虛擬化，再評估 Canvas。
- 像素素材使用 `image-rendering: pixelated`；UI 字體與文字維持目前清楚的非像素字體。

## 6. 建設工作與真實時間

### 6.1 工作狀態

施工工作採用以下狀態：

- `planned`：只在本機放置預覽，未扣款。
- `building`：已扣款並正式施工。
- `ready`：伺服器時間已超過完工時間，等待客戶端播放一次完工效果。
- `completed`：正式建築已存在，完工效果已確認。
- `cancelled`：僅供錯誤回復或管理用途，玩家一般不直接看到。

視覺階段由施工進度即時計算，不每秒寫入存檔：

- 0～15%：地基／木樁。
- 15～70%：半成品／鷹架。
- 70～100%：接近完成。
- 100%：成品，伙伴播放既有慶祝動畫並出現星光。

### 6.2 時間資料

每個工作至少保存：

```js
{
  id,
  kind: "build" | "reclaim" | "upgrade",
  buildingId,
  anchor: { q, r },
  orientation,
  workRequiredMs,
  workDoneMs,
  workRate,
  lastProgressAt,
  finishAt,
  workerIds,
  status,
  createdAt,
  completedAt,
  completionAcknowledgedAt
}
```

- 所有時間保存為 UTC ISO 字串或 epoch milliseconds；顯示時才轉成玩家當地時間。
- 不使用長時間 `setTimeout` 作為完成依據，也不在背景逐秒寫資料庫。
- 玩家進入小島、回到前景或重新連線時，以 `現在時間 - lastProgressAt` 一次結算經過的工量，再更新 `workDoneMs` 與下一個 `finishAt`。
- 農場、牧場與工廠使用相同方式，以 `現在時間 - lastSettledAt` 判斷目前這一批是否完成；完成後停在可領取狀態，不自行開始下一批。
- 物流保存 `departedAt` 與 `arrivesAt`，進入小島時一次結算已抵達的貨物與賣方金幣。
- 有網路時以伺服器回傳的 `serverNow` 為現在時間；離線畫面可先用 `Date.now()` 預覽，涉及金幣、產物或物流領取時仍由伺服器重新驗證。
- `visibilitychange`、`pageshow`、重新連線與進入小島時，都執行同一個 `settleIsland(now)`，一次處理施工、生產及物流。
- 手機背景暫停 JavaScript 不會影響工期，也不會產生任何背景資料庫流量。

### 6.3 伙伴與加速

- 第一位工人優先使用玩家頭像伙伴；若他已在其他工程，玩家必須另選並支付雇用費聘請空閒伙伴。
- 同一伙伴不能同時出現在兩筆施工工作的 `workerIds`。
- 每件工作最多再雇用 2 位不同伙伴。
- 1 位工人速度為 1.0 倍；2 位為 1.5 倍；3 位為 2.0 倍。
- 每位伙伴另有按動物印象設計的專長標籤；符合工程標籤時，該伙伴的個人工作時間縮短 20%～50%。團隊速度為「人數合作倍率 × 全隊個人速度平均」，並保存到工作的 `teamRate`。
- 第一位幫手費用建議為 `max(8, 建築費用 × 15%)`。
- 第二位幫手費用建議為 `max(12, 建築費用 × 25%)`。
- 雇用幫手只影響尚未完成的工作量，不回溯重算已經過的時間。
- 正式模式不提供金幣立即完成，讓伙伴施工仍是玩法主體。未上線測試模式可用「馬上完成」驗證流程，但 PUSH／部署前必須由單一設定開關關閉。

加人時的計算順序：先依舊速度結算 `workDoneMs`，再提高 `workRate`，最後用剩餘工量計算新的 `finishAt`。每次加人是一筆不可重複的交易。

## 7. 金幣與跨裝置一致性

目前 `mergeProgressHighWater(primary, secondary)` 已改為保留主要較新存檔的金幣與小島狀態，只有樓層、完成局數、星星與等級取高水位，避免舊裝置恢復已花掉的建設金幣。

### 7.1 建議錢包模型

- 每次收入或消費建立唯一 `transactionId`。
- 交易包含 `playerId`、正負金額、原因、關聯工作、建立時間與裝置操作 ID。
- 同一交易重送只能成功一次。
- 餘額由已確認交易推導，不能再使用 `Math.max(localCoins, cloudCoins)`。
- 舊存檔第一次升級時，把現有金幣建立成一筆 `opening_balance`，只遷移一次。
- 數獨過關、成就、提示、復活、填海、建造與雇工都逐步改走同一錢包介面。

### 7.2 離線政策

- 未啟用雲端的純本機玩家，可以在本機建島；啟用雲端時提供一次性遷移。
- 已啟用雲端的玩家，觀看小島與等待施工可離線進行。
- 扣金幣的新建、加速與未來物流操作首版要求連線，避免兩台裝置同時花掉同一筆餘額。
- 若日後要支援完整離線建設，需加入可合併的操作日誌、預留金額與衝突回復，列為後續工程。

### 8.1 本機狀態

建築規格不存進玩家存檔，只保存 `buildingId` 與實例狀態；價格、工期、占地和素材由版本化目錄提供。

### 8.2 雲端資料表

v47 migration 實際維護：

- `island_network_profiles`：玩家名稱、伙伴、可用設施與伺服器可信庫存鏡像；名單 RPC 不會公開庫存。

大型公開營運後可再正規化：

- `player_wallets`：玩家餘額與 revision。
- `wallet_transactions`：唯一交易與稽核資料。
- `player_islands`：島名、種子、等級、繁榮度、revision。
- `island_tiles`：已填海的 axial 座標與地形。
- `island_buildings`：建築實例、占地錨點、方向與等級。
- `island_jobs`：施工狀態、工量、速度、伺服器開始／完工時間。
- `island_inventory`：每位玩家、每種貨物的目前數量與保留數量。
- `facility_state`：農田、果園與牧場目前批次、`ready_at`、可領取產物，以及工廠已完成待領的彙總數量與 revision；不建立逐秒紀錄。
- `facility_jobs`：本地投入或跨島送達後自動開始的短期加工批次、`ready_at` 與產出；同一工廠可同時存在多筆工作，不設工廠容量。到期結算後會合併到 `facility_state` 的待領數量並刪除工作列。

### 8.3 身份與多人安全

目前 4 位 PIN 足以保護家庭排行的低風險操作，但不適合長期保護可交易資產。碼頭與機場開放前需要：

- PIN 驗證成功後，由伺服器簽發高熵、可撤銷、會過期的裝置 session token。
- 新裝置仍可使用玩家名稱與 PIN 恢復，但敏感 RPC 使用 token，不在每次物流操作傳送 PIN。
- 連線採邀請碼／好友邀請並由雙方接受，不公開所有玩家島嶼。
- 只公開島嶼展示資料，不公開錢包、PIN、施工內部資料或存檔碼。

### 8.4 Supabase 免費方案負載評估

截至 2026-08-09，Supabase 官方免費方案列出的主要額度為：每個專案 500 MB 資料庫、每月 5 GB egress、每月 200 萬則 Realtime 訊息、200 個 Realtime 尖峰連線、50,000 MAU、500,000 次 Edge Function 呼叫與 1 GB Storage。資料庫超過 500 MB 時免費專案會進入唯讀；免費專案閒置一週也可能暫停。官方資料見 [Pricing](https://supabase.com/pricing)、[Billing](https://supabase.com/docs/guides/platform/billing-on-supabase) 與 [Database size](https://supabase.com/docs/guides/platform/database-size)。

依本文件的事件式架構，家庭／小型玩家群不會有明顯壓力，原因如下：

- 倒數、波浪、伙伴動畫與工廠進度都在客戶端計算，不送 Realtime，也不逐秒寫資料庫。
- 進入小島時只呼叫一次 `settle_island_state`，以時間差批次結算所有設施與工作。
- 農田重用一筆 `facility_state`；加工廠每批只建立短期工作列，到期後把相同成品彙總成待領數量並刪除工作列，不永久保存每次生產歷史。
- 物流每次只有一筆 shipment，出發一寫、到貨一結算；不追蹤船隻每分鐘位置。
- 地圖美術放在網站靜態資產，不放 Supabase Storage，避免吃掉資料庫與 Storage 額度。
- 不啟用全島 Realtime 訂閱；目的地清單只在玩家打開物流面板時查詢。

建議每次進入小島的完整資料壓在 30 KB 以下。以 100 位活躍玩家、每人每天進入 5 次估算，單純小島讀取約 450 MB／月，仍遠低於 5 GB egress；若接近 1,000 位同等活躍玩家，則可能接近免費 egress 上限，屆時需要分頁、差量同步或升級方案。

資料庫真正可能膨脹的是物流與錢包歷史，因此採用：

- 已完成 shipment 保留 30 天，之後彙總成玩家月統計並刪除明細。
- 錢包詳細交易保留 90 天；更舊資料結算成不可回退的 checkpoint，只保留必要操作收據防止重送。
- 每位玩家核心島嶼、建築、貨物與工廠狀態目標控制在 50 KB 以內。
- 資料庫到 300 MB 或 egress 到 3 GB／月時先警示；450 MB 前必須清理、限制或升級。
- 不使用排程每分鐘掃描到貨；玩家進入、收件人進入或主動操作時才批次結算到期 shipment。

所以目前免費資料庫足以支撐家庭與數百名低至中度活躍玩家；它不適合在不做資料保留與差量讀取的情況下，直接承接上千名高頻物流玩家。

## 9. 生產鏈、市場與合作物流

### 9.1 生產鏈規則

- 每條產業鏈最多 4 層，來源設施也算第 1 層，市場／出口算最後一層。
- 所有原料與半成品都能在本地市場出售，因此沒有玩家合作時也不會卡死。
- 深加工售價一定高於直接出售投入原料，但要付出建地、設施金幣與加工時間。
- 玩家倉庫容量由島主小屋等級決定；容量不足只阻止領取，不刪除設施上的待領產品。每種物品仍只保存一個整數數量。
- 農田、果園與牧場每次只進行一批，成熟後等待玩家點擊收成／擠奶；領取後才開始下一批。
- 加工廠不設輸入或工作容量。每批送入的原料都建立自己的完成時間，到時自動變成成品並等待工廠主人領取。
- 配方是版本化靜態目錄；存檔只記產品數量、進行中的配方與上次結算時間。
- 初版不加入產品腐壞，降低長者玩家的壓力。

### 9.2 離線生產結算

農田、果園與牧場的目前批次保存：

```js
{
  buildingInstanceId,
  recipeId,
  cycleDurationMs,
  cycleProgressMs,
  lastSettledAt,
  readyAt,
  readyOutput,
  state: "running" | "ready",
  revision
}
```

玩家進入小島時：

1. 取得伺服器 `serverNow`；離線時暫用本機時間顯示。
2. 計算 `elapsed = serverNow - lastSettledAt`。
3. 若 `serverNow >= readyAt`，把設施標為 `ready`，但不自動把產品放入倉庫。
4. 玩家點「收成／擠奶／領取」時先驗證小屋倉庫容量；足夠才加入倉庫並開始下一批，不足則維持待領。
5. 所有已到期設施在同一個 RPC／交易內更新，只寫一次資料庫。

加工廠的每一批工作另存 `startedAt`、`readyAt`、投入與產出。自己的原料送入工廠後立即開始；其他玩家貨物抵達時自動開始。多批可以平行加工；結算時把已完成的相同成品彙總成工廠上的待領數量，直到工廠主人按「全部領取」或依產品領取，產物才加入玩家倉庫。

牧場也遵循相同流程：玩家可從自己的倉庫送玉米餵牛並開始產奶；其他玩家送來的玉米抵達牧場時則自動開始該批產奶。時間到只顯示可擠奶，玩家點擊後牛奶才進倉庫，再決定直售、送自己的食品工廠或送往其他玩家工廠。

### 9.3 本地市場

- 市場是所有可出售物品的保底出口，確保貨物永遠有用途。
- 玩家從小屋倉庫選擇數量後可以立即出售，不設市場容量或等待時間；在途船機不可出售。
- 原料售價最低、半成品次之、完整成品最高。
- 市場售出才建立錢包收入交易；農田成熟或工廠完工只變成可領取狀態，不直接發貨物或金幣。
- 每日可加入 2～3 個需求品項，例如今日蔬菜 +20%，提高產業輪替，但不能讓其他貨物完全賣不掉。

### 9.4 玩家工廠目的地

玩家 B 的牧場、磨坊、食品工廠等設施可以開啟「接受合作物流」，並由系統發布相容收貨需求。需求包含：

- 接受品項與數量。
- 對應工廠與加工後的產品。
- 到貨後玩家 A 可取得的固定金幣。
- 預計海運／空運時間。
- 需求到期時間與是否只限已連線好友。

玩家 A 有碼頭後，從自己的倉庫選擇貨物，只會看到「擁有相容工廠且已開放收貨」的玩家。加工廠不設容量，因此不必預留空位；每批貨物抵達後都建立一筆獨立加工工作。

若玩家 B 有市場，A 也可以選擇「賣到 B 的市場」。這種 shipment 抵達後直接成交，不在 B 的島上建立加工批次。跨島市場採 `ceil(本地市場價 × 1.75)` 的伺服器可信價格，介面同時顯示跨島與本島金額。

建議合作報酬為本地市場原料價的 115～125%。例如玉米本地每箱 4 金幣，送往 B 的牧場可在到貨時獲得每箱 5 金幣。B 不直接支付自己的金幣，而是由系統合作訂單支付；玉米抵達後自動開始產奶，時間到等待 B 點擊擠奶，因此雙方都有利益，也不要求 B 當下在線。

合作收入需要以下限制：

- 不限制工廠可同時加工的批次；出貨速度受 A 的貨物、航程與持有載具數限制。
- 若實測出現兩個帳號互刷，再以碼頭船位或每日合作報酬遞減處理，不用工廠容量限制正常合作。
- 報酬在出發時鎖定並寫入 shipment，後續改價不影響在途貨物。
- 工廠有在途或加工中工作時不能拆除；移動建築不改變 shipment 目的地。
- 接收者可以關閉新訂單，但已出發貨物仍會正常送達。

### 9.5 碼頭、機場與運輸時間

物流與加工使用兩個相連的非同步狀態機，不做即時連線遊戲：

- shipment：`in_transit → arrived_paid`
- facility job：`processing → ready → collected`

兩者另保留 `cancelled` 與 `failed` 供安全回復。

- 碼頭必須占用一格陸地與一格相鄰海面，依海岸方向需要 6 種朝向。
- A 玩家需要碼頭＋至少一艘物流船才可海運，或機場＋至少一架物流飛機才可空運。B 必須有相容工廠或市場，不必有物流設施。
- 每艘船／飛機同時只服務一筆在途 shipment；增加持有量就增加併發班次。
- 海運基礎航程 60 分鐘、單次 20 件；船從碼頭海面 footprint 做海格 BFS，只能沿海洋格前進。
- 機場占用 1 格陸地，基礎航程 15 分鐘、單次 8 件；飛機可直線越過陸地。
- 出發時先扣除 A 倉庫中的貨物；不能等抵達才扣，避免同一貨物重複出貨。
- shipment 保存 `departedAt`、`arrivesAt`、`sellerRewardCoins`、貨物與目的工廠。
- 玩家再次進入、A 或 B 開啟小島、或執行其他物流操作時，`settle_due_shipments` 會批次處理所有到期 shipment。
- 到貨結算在一筆資料庫交易中同時完成：金幣加入 A 錢包、shipment 標為 `arrived_paid`、B 的工廠建立 `processing` 工作，並計算 `processingReadyAt = arrivesAt + recipeDuration`。
- 加工時間到後，工作產出彙總到工廠的待領數量並標為 `ready`；B 點擊領取且倉庫容量足夠後，成品才加入小屋倉庫。
- A 不需要按「領取」；下次同步會直接看到到貨收入。即使 A 離線，只要 B 或系統下一次結算該 shipment，A 的錢包也會更新。
- A 首次同步到每筆抵達報酬時會收到一封自動感謝函；shipment ID 防止重複彈出。
- 地圖上的船與飛機只依出發／抵達時間播放位置動畫，不寫回船隻座標，也不是完成判定來源；已出貨明細只能查看，不能修改。

## 10. 程式模組規劃

核心規則與畫面不堆進目前的大型 `src/app.js`。Foundation 與物流已建立以下模組；控制器暫由 `app.js` 負責畫面切換與事件接線：

```text
src/
```

### 11.1 現有可重用素材

- 25 種伙伴各 4 個舞蹈版本，共 100 個 220×220、30 幀透明 Animated WebP，總計約 13.6 MB。

- `friends-dance/*.webp`：建設完成慶祝、遊樂場活動。

- 花園鰻：可成為海岸稀有裝飾事件。

### 11.2 建議風格

以下標準命名為 **SUDOX Buddy & Island Style v1**。其他 AI 生成任何伙伴、建築、產品、載具或動畫時，都要附上此 Style ID、使用的參考圖、prompt、seed／job ID 與生成日期，方便重製。

#### 11.2.1 現有小伙伴的明確風格定義

角色定位為「兒童貼紙感的圓潤 chibi 動物」，不是寫實動物、日系大眼角色，也不是硬邊 8-bit 像素角色。

形體：

- 單一完整動物，全身入鏡，透明背景，沒有場景、底座、文字或外框貼紙白邊。
- 正面或接近正面，整體近似左右對稱；海豚、鯨魚等體型需要時可採清楚的側面剪影。
- 大頭、短身、短肢體、低重心；形體主要由圓形、橢圓與柔和曲線組成。
- 耳朵、尾巴、角、鰭等物種特徵必須在縮到 64 px 時仍可辨識。
- 不畫毛髮絲、羽毛細紋、皮膚毛孔或寫實肌肉；斑紋最多使用大面積色塊。
- 手腳只用簡單圓頭線條或 0～3 個趾端提示，禁止寫實手掌。

臉部：

- 眼睛為兩個大小接近的純黑圓點或短橢圓，不加虹膜、睫毛、高光或漸層眼珠。
- 鼻子為簡單黑色橢圓、圓角三角或物種必要造型。
- 嘴巴只用 1～2 條圓頭黑色曲線；表情友善、安心，不能露出寫實牙齒。
- 腮紅可用兩個低飽和粉橘色橢圓，透明度與尺寸保持克制。

線條與顏色：

- 最外輪廓使用近黑色 `#050505`，1024 px 主圖建議 22～32 px 粗；縮成 220 px 後約 5～7 px。
- 輪廓寬度近似一致，端點與轉角全部圓滑；不能有鉛筆、蠟筆、水彩或顫抖手繪線。
- 每個角色以 2～5 個主色塊構成，保留高辨識度的物種原色。
- 可有非常輕微的同色系明暗漸變或下方陰影，但明暗差不超過約 12%；禁止高光反射、材質紋理與戲劇性光影。
- 共用輔助色：暖白 `#F8F6EE`、奶油 `#FFF0DF`、腮紅 `#F3978D`、深線 `#050505`。
- 新角色顏色需能和 UI 主色 `#FF936F`、`#86CFB5`、`#344256`、`#FFFAF2` 同畫面共存。

構圖與比例：

- 靜態主圖固定 1024×1024 RGBA。
- 一般角色透明 bounding box 約占畫布寬 58～72%、高 60～72%；長尾、鯨魚、海豚可放寬至寬 82%。
- 角色水平中心約在畫布 50～55%，腳底／身體底部落在畫布高度 82～88%，保留上方呼吸空間。
- 不裁耳、角、尾巴、腳或工具；所有方向版本的腳底 anchor 必須一致。
- 在 64×64 預覽時，眼睛、嘴巴、主色斑紋與物種剪影仍需清楚。

禁止項目：

- 寫實、3D 公仔、黏土、絨毛玩具、攝影、油畫、水彩、素描、漫畫網點。
- Anime 大眼、眼睛高光、複雜服裝、過多配件、尖銳陰影、霓虹光、金屬反射。
- 白色描邊貼紙框、背景色、地面、文字、logo、浮水印。
- 額外肢體、錯誤腳數、工具穿過身體、左右斑紋在動畫中跳動。
- 半透明黑邊、白色 halo、髒 alpha、模糊輪廓與 JPEG 壓縮雜訊。

#### 11.2.2 伙伴動畫標準

- 生成時必須以對應 `friends/{id}.png` 作為角色參考，保持臉、色塊、尾巴、耳朵與身體比例一致。
- 鏡頭、畫布、角色大小與腳底 anchor 全程固定；禁止推鏡、縮放、旋轉整張畫布或背景晃動。
- 工作動畫建議輸出 220×220 RGBA Animated WebP、24～30 幀、12～15 fps、總長 1.6～2.2 秒並可無縫循環。
- 第一幀與最後一幀姿勢接近；循環處不能瞬移、變形或突然多出工具。
- 位移幅度以角色高度 8% 內為原則，工具可以超出身體但不能超出畫布。
- 左右工作方向先製作單一版本，再以程式鏡像；有文字或明顯不對稱工具時才另外生成方向版。
- 每段動畫只表達一個動作：敲打、挖土、澆水、搬箱、採收、裝貨或慶祝，不把多個工作混在同一循環。
- 建設完成繼續沿用現有 220×220、30 幀舞蹈 Animated WebP，避免重做整套慶祝動畫。
- 動畫單檔目標低於 180 KB；透明邊緣乾淨，縮至 64 px 仍不閃爍。

#### 11.2.3 六角地圖、建築與產品風格

- 地圖採「柔和像素風」：輪廓與色塊有明確像素群，但配色明亮柔和，不採暗色低色數 8-bit 風。
- 視角固定為正交 3/4 俯視，約 35° 高度，正面朝畫面下方；禁止透視消失點與魚眼變形。
- 光源固定由左上方照射，陰影短而柔和地落向右下；同一建築的施工階段不能改變光源。
- 建築輪廓使用深藍灰 `#344256` 或近黑色，門窗、農作物與招牌在 64 px 格寬下仍可辨識。
- 每張建築控制在約 24～40 個顏色，不使用照片材質、細碎噪點或過度漸層。
- 生產設施必須從剪影看出用途：菜園可見菜畦，牧場可見牛棚，食品工廠可見乳品槽／包裝箱，市場可見棚架與貨攤。
- 產品圖示採相同粗輪廓、單物件、透明背景，不能依靠文字標籤辨識。
- 施工中的三階段要保留成品 footprint 與主要輪廓：地基、約 50% 半成品、約 85% 接近完成。
- 建築正面固定朝下；只有碼頭、道路、橋與船隻製作 6 個六角方向版本。
- 地圖使用 nearest-neighbor；文字、按鈕、倒數與進度環保持平滑，避免閱讀困難。

## 13. 效能、PWA 與無障礙

- Service Worker 只預快取小島核心地形、manifest 與必要 UI；25 種伙伴和大型建築按需下載並快取。
- 小島素材放在版本目錄 `island/v1`，更新時更換版本並同步提高 PWA cache 名稱。
- 地圖離開畫面後停止動畫與倒數重繪，但不停止真實時間工作。
- Animated WebP 僅在可見格與施工中的伙伴播放；移出可見區域改用靜態幀。
- 同畫面施工伙伴建議不超過 6 位，避免大量動畫解碼。
- `prefers-reduced-motion` 時停用波紋、伙伴循環與星光，顯示靜態代表幀。
- 所有建築都有文字名稱、狀態與剩餘時間，不只依賴顏色或動畫。
- 390×844、430×932、iPad 直向與橫向都要驗證；底部面板避開 iPhone safe area。

## 15. 測試與驗收

### 15.1 自動測試

- 六方向鄰接、距離、半徑與畫面座標。
- 多格 footprint 旋轉、越界、重疊與地形限制。
- 只能填造相鄰海格。
- 關閉後重開、跨日、背景暫停與已逾期工作的完成判定。
- `serverNow - lastSettledAt` 能一次正確結算多座設施、多個完整批次與剩餘進度。
- 農田成熟後只保留一批待收成，領取前不會因更多離線時間重複產生產品。
- 每一筆本地或跨島加工工作只能轉成一次待領成品，領取後只增加一次倉庫數量。
- 中途增加第一／第二位幫手後的剩餘工量與完工時間。
- 同一 `operation_id` 重送不重複扣金幣。
- 兩裝置競爭建設時只能有一筆成功。
- 存檔版本遷移、素材缺失 fallback、雲端中斷與重試。
- 裝飾移動不影響施工建築或占地資料。
- 本地市場售出、合作 shipment 到貨與錢包付款各自只能結算一次。
- 出發時會原子扣除 A 倉庫貨物並建立 shipment；失敗時兩者都不改變。
- B 離線時 shipment 仍能到期，A 或 B 下次進入即可批次完成付款與收貨。

### 15.2 瀏覽器驗證

- iPhone 390×844 可完整操作，沒有橫向溢出或底部面板遮住目標格。
- 單指拖曳不誤觸建造；短點擊仍能可靠選格。
- 縮放後像素素材不模糊，文字與倒數仍清楚。
- 進背景兩小時再回來，果園正確完成且只播放一次完工效果。
- 關閉頁面跨越數個生產週期後，農場只呈現一批可收成，不會自動連續生產；加工工作則各自依完成時間變為可領取。
- 離線可進入已載入的小島，恢復連線後正確更新。
- 開啟 reduced motion 時所有必要資訊仍可理解。
- 現有數獨、提示、復活、寶物、排行榜與雲端存檔完整回歸。

## 16. MVP 完成定義

以下全部達成才視為小島建設 MVP 完成：

- 新舊玩家都能建立唯一小島，重載與換裝置後不遺失。
- 7 格初始島、填海、合法放置、多格占地與建築移動規則正確。
- 兼作五級容量倉庫的島主小屋能正確預建／升級；所有設施能完整施工與拆除，單格機場可在一般空地開工。
- 每項工程立即出現半成品與工作伙伴。
- 果園等 2 小時工程不需保持頁面開啟也能完工。
- 蔬菜可以在市場換金幣；玉米可以直售或送牧場，牛奶可以直售或送食品工廠，乳製品可以高價出售。
- 每座生產設施依上次結算時間在玩家進入時一次補算，沒有逐秒資料庫更新。
- 雇用伙伴會正確縮短剩餘時間，不能重複扣款或造成負金幣。
- 同一伙伴不能同時參與兩筆施工；自己的伙伴忙碌時可聘用另一位空閒伙伴開始新工程。
- 舊裝置資料不會恢復已花掉的金幣。
- 手機操作、離線顯示、PWA 更新與 reduced motion 都通過驗證。
- 碼頭與機場的位置、占地、海空運與跨玩家事件交接可完整操作，重送不會重複扣貨或發獎。

## 17. 建議確認項目

若沒有另外調整，實作將採用以下預設：

1. 平頂六角格、初始 7 格、半徑 8 共 217 格；舊存檔自動擴張且不移動既有內容。
2. 柔和像素地圖搭配現有圓潤伙伴，不把 25 種伙伴全部重畫成硬派 8-bit。
3. 果園基礎工期 2 小時；最多 2 位幫手，最高 2 倍施工速度。
4. 首版完成蔬菜直售、四層乳品鏈與跨玩家合作加工；所有產品仍有市場保底出口。
5. 生產與施工都在玩家進入時用上次結算時間補算；雲端資產以伺服器時間為準，不做逐秒背景更新。
6. 玩家 A 可把相容原料送往玩家 B 已開放收貨的工廠；到貨後系統付款給 A，B 的工廠自動開始加工，完成後等待 B 點擊領取。
7. 玩家倉庫隨小屋 5 級擴建；農場、牧場與工廠完成後先停在設施，容量足夠才能領取。
8. 加工廠不設輸入或工作容量，多批可以平行計時；到期工作彙總成待領產品以控制資料量。
9. 首版雲端玩家的新建、雇工、出售與出貨需要連線；已開始的工程與生產可離線等待與觀看。
10. 先完成「海岸＋填海＋菜園＋市場＋蔬菜產品＋貓工作動畫」風格樣板，確認後才批量製作正式素材。
